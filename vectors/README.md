# Test vectors

Generated by `scripts/vectors.ts` from two committed **test-only** Ed25519
keys in `keys/` and a fixed counter clock. Ed25519 is deterministic, so
`pnpm vectors:check` must report byte-for-byte reproduction; the verify test
suite asserts it.

The keys in `keys/` are public on purpose. They sign nothing outside this
directory and are never accepted by a gateway. A real witness key is generated
by `pnpm keygen` into the gitignored `keys/` at the repository root.

| file | expected | what it exercises |
|---|---|---|
| 01-good | INTACT | FINALIZED, paid REFUSED, zero-cost REJECTED, FAILED+REJECTED, correction, ANCHOR, unpaid OBSERVED |
| 02-edited-payload | chain breaks at 1 | payload edited after signing |
| 03-deleted-entry | chain breaks at 3 | an entry removed |
| 04-reordered | chain breaks at 4 | two entries swapped |
| 05-forged-signature | 1 bad event, chain intact | event re-signed with `keys/forger.jwk.json`, then every hash recomputed: an attacker holding the file can re-chain, but cannot sign |
| 06-bad-anchor-root | 1 bad anchor, chain intact | anchor root altered, hashes recomputed |
| 07-malformed-record | 1 structural defect, chain intact | EVENT missing `event.ts`, hashes recomputed (schema and built-in checks must agree) |

02 to 04 are naive tampering (the chain catches them). 05 to 07 are
sophisticated tampering (the chain is consistent; the signature, anchor and
structural checks catch them). A verifier that only checks the chain passes
05 to 07 and is therefore insufficient.

Anyone can validate these with `docs/schema/truth-record-v1.schema.json` and
`pnpm verify vectors/01-good.json` after converting to JSONL, or directly with
`verifyEntries()` from `packages/verify/src/cli.ts`.
